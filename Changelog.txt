Unreleased
- reproducible build: sketch.yaml (arduino-cli profile) pins the ESP32 core 3.3.13 and all library
  versions; MAX31855 fork and Syslog are git submodules; GitHub Actions builds firmware and data image
- TEMPLATE_PLACEHOLDER is passed as a build flag - no manual edit of the ESPAsyncWebServer library
- filesystem moved from SPIFFS (deprecated) to LittleFS - see README "Upgrading": the first boot
  formats the old SPIFFS partition, back up programs and pidkiln.conf first
- built-in fallback upload page when the filesystem has no web interface files
- web flash page accepts LittleFS data images (file name containing "littlefs")
- fixed deleting rejected program uploads (removed the wrong path since ESP32 core 2.0)
- replaced deprecated ICACHE_RAM_ATTR and a raw ESP32 efuse register read with current APIs
- security: firmware flashing and program upload checked the password only after the upload was
  processed - now checked in the upload callbacks; /load.html, /delete.html and /screenshot.html
  require login; state-changing requests from other web sites are rejected (CSRF)
- security: program names from requests are validated and bounded (fixes a stack overflow in
  /load.html); preference values and program descriptions are HTML-escaped (XSS)
- safety: a program can't be loaded or replaced (web, LCD, quick program) while one is active -
  this used to stop the PID loop and could leave the heater switched on
- safety: aborts (safety checks, sensor errors, Abort button) now also work while waiting for the
  temperature threshold; they were ignored in that state
- safety: firmware flashing is refused while a program is active; restart after flashing is done by
  the program loop instead of inside the web handler
- Start no longer restarts an already running program; a changed PID_POE applies during a run
- safety: a step with 0 minutes to reach its temperature jumps the set point to that temperature;
  it used to divide by zero, and with an unchanged temperature the PID stopped heating for the rest
  of the run while the program still showed "Running"
- safety: the program aborts (Program_error 15) if the temperature, set point or PID output becomes
  NaN or infinite
- program files are checked strictly: exactly three numbers per step (load error 14 otherwise, also
  for values above 65535 and for files without steps), at most 40 steps (load error 15 - fixes a
  memory overrun); program lines of 15 characters no longer overflow the parser buffer
- fixed buffer overruns from long program descriptions on the LCD and from long file names in the
  programs/logs directories (such files are now skipped); fixed reading out of bounds when the
  program list is empty (the LCD now says "No programs found")
- fixed undefined behaviour in debug logging of messages longer than their format string
- safety: Thermal_Runaway is implemented (it was documented but never used): abort with error 16 if
  the kiln does not gain 5C within that many minutes while the set point is 5C+ above it. Still off
  by default (0); the code default was 130, now 0 like pidkiln.conf; added to the preferences page
- safety: stuck SSR detection - if the kiln warms up by 25C while the SSR is commanded off, a running
  program aborts with error 17 (opens the EMR); without a running program the alarm is switched on
- safety: task watchdog enabled again (15 s) for the program loop - a hang now restarts the ESP32,
  which switches the relays off; relays and alarm are driven off explicitly at boot. The input loop
  no longer busy-loops (it starved the idle task, the likely reason the watchdogs were disabled)
- safety: temperature limits are checked every second instead of every 10 s, and the MAX and
  housing limits also without a running program (relays off, alarm on)
- MIN_Temperature can be negative
- thermocouple faults abort with the K-probe error codes (8/11) instead of the internal-sensor ones
- fixed GMT offsets above 9.1 hours (configTime and the preferences page read the INT32 pref as
  16 bit); initial date/time parsing no longer copies into a fixed buffer or leaves struct tm fields
  uninitialised, and tolerates missing parts
- log files: the footer shows the used energy (it printed the current power, wrongly formatted), and
  "CSV filename" shows the file name instead of a date
- LCD preferences screen: values shown according to their type (it printed string pointers as
  numbers), no read past the end of the preferences table, no buffer overrun for long values
- the web server registers its handlers once - a WiFi reconnect used to register them all again;
  a changed web login applies to all pages right away (static pages kept the old one until reboot)
- program upload: a failed structure check shows its error page (a redirect replaced it), and no
  longer makes the next upload fail; LCD main view and graph fixes (title width, unset scales)

1.2 (2021.12.02)
- extended error reporting for MAX31855 and thermocouples
	[ADDONS] Temperature sensor A readout: Internal temp = 26.1 	 Last temp = 24.2 	 Average kiln temp = 20.9
	[ADDONS] ThermocoupleA not connected
	[ADDONS] MAX31855 for ThermocoupleC did not respond
- lowered SPI clock value for less errors during communication handling (in MAX31855 library)
- new feature allowing grace count for errors in MAX31855 readout, from pidkiln.conf:
  # How many thermocouple A and B errors combined, we can tolerate without aborting program.
  # If you have sporadic thermocouple read errors, you can increase this value.
  MAX31855_Error_Grace_Count = 5
- you can now use Wroom modules (without PSRAM) - change MALLOC definition in PIDKiln.ino
- fixed stupid stack overflow in IP display routine
- Updated SPIFFS handling to make it compatible with ESP32 2.0.x+ Arduino framework (it has change silently)
